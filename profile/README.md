### 🐙 GitHub 협업 가이드라인 (Workflow & Convention)
| 구분 | 목적 | 세부 전략 |
| :--- | :--- | :--- |
| **Branch** | **전략적 브랜치 관리** | • `main`: 배포 전용 (직접 커밋 지양)<br>• `feature/기능`, `fix/버그`: 작업 브랜치 생성<br>• 습관적 `git pull`로 충돌 방지 |
| **Commit** | **커밋 컨벤션 준수** | • 형식: `type: 요약` (예: `feat: 이동 구현`) <br>• `feat`(기능), `fix`(수정), `docs`(문서), `refactor`(개선) |
| **Code** | **코드 및 주석 규칙** | • 팀별 Naming Convention 준수<br>• 코드 의도 전달을 위한 주석 작성 생활화 |
| **PR & Review** | **안정성 확보 절차** | • 작업 완료 후 `develop` 브랜치로 PR 생성<br>• 최소 1명 이상의 Approve 후 머지 가능<br>• 직관적인 관리를 위해 **GitKraken** 활용 권장 |
